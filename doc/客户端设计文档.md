# Parrot 桌面客户端设计

更新日期：2026-11-19。平台：macOS 13+。应用版本：1.0.0。

## 1. 产品形态与交互

Parrot 默认以原生 `.app` 启动，通过一个 64pt 透明窗口中的圆形悬浮球常驻桌面，首次默认显示于左侧。用户点击球展开转写面板，再次点击、面板收起按钮或系统关闭按钮均收起面板。收起保留 WKWebView 和后台任务，持续采集、识别和写入文字。

悬浮球可以拖动。拖动过程中限制在当前显示器可用区域内，松开后保留当前位置，不吸附边缘；横向和纵向位置以比例保存，同时记录显示器标识，后续启动恢复。显示器断开或可用区域变化时将位置限制在现有屏幕内。窗口位于 floating 层，允许出现在多个桌面和全屏应用空间。系统的特殊全屏、屏幕锁定和窗口管理策略仍可能影响其显示。

面板默认约 620 × 740pt，邻近悬浮球展开，按屏幕空间限制位置和大小；优先选择有空间的一侧，靠右放置时向左展开，避免面板越界。顶部提供新建、历史、设置和收起。正文以转写内容和 Markdown 为主，识别设置与历史记录通过弹窗打开，减少对课程画面的占用。

悬浮球下方状态点表示服务状态：服务连接失败时橙色，空闲时灰色，有任务时绿色。不是准确率、完成百分比或严格的录音就绪指示；具体准备、采集和收尾状态在面板中显示。

菜单栏提供显示/收起、设置和退出。客户端采用 accessory 激活策略，不以普通 Dock 主窗口作为入口。关闭面板不是退出程序；退出以菜单栏操作为准。

## 2. 架构与模块

`native/ParrotDesktop.swift` 使用 AppKit 创建悬浮球 NSPanel、工作区 NSPanel、菜单栏与系统对话框。工作区通过 WKWebView 承载 Vue 3 + Ant Design Vue，使用系统 WebKit，无需安装 Electron 或依赖独立浏览器。

原生客户端拥有一个 Python 子进程，执行 `backend.desktop_server`。该进程运行单 worker FastAPI，复用现有任务、分段、Whisper、SQLite 和导出逻辑。采集仍由应用包内的 `ParrotCapture` 通过 ScreenCaptureKit 执行。

关键文件：

- `native/ParrotDesktop.swift`：窗口、拖动、菜单、进程生命周期、桥接与原生集成自检。
- `frontend/src/desktop.ts`：客户端能力检测、令牌请求头、原生复制/导出/收起封装。
- `frontend/src/App.vue`：紧凑工作台、设置与历史弹窗，继续轮询实际后端状态。
- `backend/desktop_server.py`：客户端专有服务入口及原生父进程监控。
- `backend/main.py`：增加桌面令牌校验，提供转写、暂停/继续、校对及导出接口。
- `scripts/build-client.py`：编译、资源打包、图标与本机签名。
- `scripts/test-client.py`：使用隔离数据运行真实原生客户端自检。

## 3. 启动与单实例

原生进程先确定数据目录，取得 `desktop.lock` 文件锁，再创建悬浮球、工作区和后台服务。同一数据目录只允许一个客户端拥有者。锁带 close-on-exec 标记，避免 Python 子进程继承后妨碍再次启动。

服务端口通过回环 socket 临时绑定 0 获取，再交给 Python 使用。端口交接之间仍存在极小的抢占窗口；若绑定失败，客户端展示启动错误而不连接其他不受信任服务。

访问令牌由两个 UUID 拼接，每次启动重新生成，仅存在于原生进程、子进程环境和注入的客户端页面中，不写入诊断文件。客户端带令牌轮询 `/api/status`，就绪后加载面板资源。

启动默认只显示悬浮球和菜单栏，界面资源在后台加载。首个模型不会因启动客户端而自动加载，用户开始聆听或在设置中预加载时才加载。

## 4. WebKit 桥接

原生宿主在 document-start 为主 frame 注入只读的 `__PARROT_DESKTOP__` 配置和 `parrotNative` 能力。`request(action, payload)` 返回 Promise，独立 UUID 请求 ID 与原生回复对应；`send` 用于不需要响应的状态与收起消息。

动作限定为：

- `collapse`：隐藏面板，不停止采集。
- `state`：更新悬浮球的连接、活动和电平展示。
- `copy`：调用 NSPasteboard 复制 Markdown。
- `capturePermission`：仅在点击开始时检查或请求系统声音所需的录屏权限。
- `openCaptureSettings`：响应用户操作，打开系统录屏权限设置。
- `export`：优先使用页面传入的当前 Markdown 文稿；旧调用未传文稿时按 `sessionId` 从后端获取。显示 NSSavePanel，由用户选择保存位置后原子写入。

桥接只接受主 frame、当前回环主机与端口的消息。页面导航仅允许本服务；用户明确点击的 HTTPS 外部链接可交给系统打开。转写和 Markdown 仍以文本显示，不将用户内容作为 HTML 执行。

取消保存对话框返回 `saved=false`，前端不显示成功消息。系统剪贴板和文件写入只由对应用户操作触发。原生自检模式使用内存复制及测试目录替代真实剪贴板和交互式保存位置。

## 5. 后台运行与退出

原生端每秒读取服务状态，避免仅依赖隐藏 WebView 的定时器更新悬浮球。活动任务期间使用允许系统空闲睡眠的用户活动标记，减少 App Nap 对实时处理的影响，不强制阻止电脑睡眠。

面板被关闭或收起时，WKWebView 和 Python 进程均保留。客户端退出时先停止当前采集，等待队列处理完毕。每等待 30 秒仍未完成时，提供继续等待或立即退出的选择；立即退出可能丢失未识别内容。

最后向客户端拥有的 Python 子进程发送中断信号，最多等待约 10 秒后结束仍未退出的进程。单独的 `backend.desktop_server` 监控父进程；原生宿主异常消失时先触发后端正常退出，约 15 秒后对仍未退出的服务执行兜底退出。强制结束仍可能留下未清理的临时片段，不能保证崩溃恢复全部文字。

客户端不接管、不停止任意其他 Python 服务。迁移前应关闭旧的独立开发后端；不要让它与客户端同时使用同一个数据库，以免遗留状态恢复逻辑干扰活动任务。

## 6. 本地访问与安全

客户端后端仅绑定 IPv4 回环地址，`/api/`、`/docs`、`/redoc` 和 `/openapi.json` 需要匹配的 `X-Parrot-Token`。令牌使用常量时间字节比较，不正确或缺少令牌时返回 403。原有 Host 与 Origin 检查继续生效。

静态界面资源本身不含令牌。普通浏览器即使访问到随机端口，也不能仅靠加载 HTML 查询笔记或启动转写。该机制用于本机客户端隔离，不构成多人服务认证、恶意本地进程隔离或公网部署方案。

开发入口 `scripts/start-backend.sh` 不默认启用客户端令牌，供 Vue 独立开发使用，应使用独立数据目录并仅监听本机。

## 7. 数据兼容与环境

本机构建把 Python 解释器位置和默认数据目录写入 Info.plist。默认数据目录仍是构建项目的 `.data/`，复用现有 SQLite 和模型缓存；不移动、不删除历史文件，也不把用户数据复制进应用包。

- `PARROT_DATA` 可覆盖客户端数据目录。
- `PARROT_PYTHON` 可覆盖构建/测试时的解释器路径。
- `PARROT_CAPTURE_BINARY` 由客户端设置为应用包内的采集程序。
- `PARROT_DESKTOP_TOKEN` 由宿主为子进程设置，用户不应固定保存或打印。
- `PYTHONPATH` 与 Python 缓存目录由宿主设置为打包运行目录及数据目录。

`desktop.log` 记录服务输出。`desktop-state.json` 记录宿主 PID、后端 PID、随机端口和窗口可见状态，不记录令牌、文字或音频。正常退出会删除状态文件。模型依旧首次下载后缓存，客户端启动本身不下载模型。

系统采集授权主体为 Parrot 客户端。点击开始时由原生宿主调用 `CGPreflightScreenCaptureAccess` / `CGRequestScreenCaptureAccess`，未获允许时不创建转写任务、不加载模型，界面提供打开系统设置入口；不会在启动或轮询时请求权限。采集组件仍以实际 ScreenCaptureKit 启动结果为准，权限错误与其他采集错误分开提示。设置权限后可能需要彻底退出并重启。

`scripts/setup-signing.py` 首次在 `.data/signing/` 建立固定的本地开发证书及独立钥匙串。临时私钥在导入完成后删除，钥匙串内私钥设为不可导出，访问限于签名工具；不安装系统信任根。该目录权限为 0700，钥匙串解锁凭据和配置为 0600，不进入版本控制。代码签名使用同一证书，主程序标识为 `com.alverlin.parrot`，采集程序为 `com.alverlin.parrot.capture`，按从内到外顺序签名。开发证书不用于公开分发。

构建默认要求固定身份；配置缺失或钥匙串丢失时失败，不自动重新生成证书或降级。`PARROT_SIGNING_IDENTITY` / `PARROT_SIGNING_KEYCHAIN` 可显式选择 Apple 证书，`PARROT_ALLOW_ADHOC=1` 仅用于临时测试。由旧临时签名首次迁移、更换证书或遗失签名目录时需要重新授权。新应用在临时目录内完成构建和签名校验后才替换原包，构建失败保留原包。

## 8. 打包边界

输出 `dist/Parrot.app` 包含原生宿主、采集辅助程序、后端 Python 源码、前端静态资源及图标。当前产物使用本机 `.venv`，没有捆绑完整 Python、识别依赖或模型，属于本机开发客户端，不是跨机器即装即用的独立发行包。

下一阶段如果需要分发，应设计 Python/模型依赖打包、CPU 架构兼容、数据目录迁移、开发者证书签名、公证、更新机制和权限连续性。当前默认不修改用户登录项，不自动开机启动，也不安装到系统 Applications 目录。

构建时只能清理生成的 `dist/Parrot.app` 和图标目录，不能清理 `.data/`。更新前退出客户端再重建，避免覆盖正在运行的资源。

## 9. 验证

后端现有流程测试继续覆盖无文件导入、无录音保存、临时片段清理、紧凑 Markdown 和异常处理；新增桌面令牌测试。当前共 17 项 pytest 用例。

`scripts/test-client.py` 在临时数据库中创建已完成的文字记录，执行真正的 AppKit/NSPanel/WKWebView/Python 服务，验证悬浮球显示、拖动边界、展开收起、收起后服务存活、桥接复制/导出、历史列表、设置、未授权请求被拒绝，以及没有导入和播放器。

测试短暂显示原生窗口，使用独立数据目录，不自动采集系统声音、不加载识别模型、不修改实际笔记。客户端截图和导出样本位于 `.data/client-test-artifacts/`，应保持在版本控制之外。

仍需要以真实课程验证客户端授权后的系统声音识别，以及不同屏幕、全屏空间和长时间连续转写的行为。本次客户端自检不等于完成所有硬件和长期稳定性验证。

## 10. 暂停与继续

聆听期间胶囊控件依次展示计时、蓝色描边的暂停/继续圆按钮、蓝色实心停止圆按钮和音量指示。暂停只作用于当前记录，停止仍结束整条记录。暂停期间计时保持不变，已经采集到的尾部及待处理片段继续转写。

`POST /api/sessions/{sid}/pause` 仅接受 `recording` 状态，将状态设为 `pausing` 并终止当前采集辅助进程。管道排空、尾部提交后才进入 `paused`，此时不存在采集进程。暂停不是挂起进程，不会在系统管道内积累暂停期间的声音。

`POST /api/sessions/{sid}/resume` 仅接受 `paused` 状态，进入 `resuming`，重新启动采集进程；收到 `READY` 后恢复 `recording`。复用原记录、模型和累计采样位置，分段文件序号递增，暂停边界清除重叠上下文。累计时长仅包含实际采集的音频。非当前任务或不允许的状态返回 409，未知记录返回 404。

暂停任务仍占用当前会话，不能同时新建第二条聆听任务。停止和退出会唤醒暂停等待，正常收尾；服务重启将 `pausing`、`paused`、`resuming` 一并标记为 `interrupted`，保留已完成的文字。
