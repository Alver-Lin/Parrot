# Parrot 开发设计文档

文档版本：2.0  
对应应用版本：1.0.0  
编写日期：2026-11-19  
适用范围：当前仓库已实现版本，以及在此基础上的后续开发。

本文依据 `backend/`、`frontend/`、`native/`、`scripts/` 和 `tests/` 的现有代码编写。除「后续演进」及明确标注的建议外，描述均指当前实现。历史验证结果参见 [验证记录](../docs/VALIDATION.md)，运行入门参见 [项目说明](../README.md)。当前默认以 macOS 客户端运行，悬浮球、原生窗口与宿主生命周期详见 [客户端设计文档](./客户端设计文档.md)。

## 1. 背景与目标

用户观看课程视频时，需要反复复习知识。手工记录视频结构、插入截图，再交给 AI 补全笔记，会打断学习过程。Parrot 的长期目标是将视频中的声音、画面与知识结构沉淀为可回看、可修改的 Markdown 学习资料。

当前版本先完成音频到文字的基础链路：采集电脑正在播放的系统声音，在本地识别中英文，保留片段时间信息与文字，支持人工校对并导出 Markdown。

主要设计目标：

- **便于开始学习**：直接采集系统声音，戴耳机时仍可使用。
- **优先保证可校对性**：保存转写文字与识别原文，支持人工编辑；1.0 不保存完整录音或提供回听。
- **减少人工搬运**：从开始采集到导出文本在同一界面完成。
- **支持本地运行**：无需语音识别 API Key，音频不提交到云端识别服务。
- **便于持续开发**：分离采集、分段、识别、存储与界面职责。

### 1.1 当前范围

已实现系统声音采集、中英文转写、时间戳、待校对标记、历史记录、逐段修改和 Markdown 导出。

当前不包含自动截图、章节提取、知识总结、复习卡片、说话人区分、云端账户、多人协作，也没有实现 Windows/Linux 的系统回环音频采集。1.0 不提供音频或视频文件导入。Windows/Linux 暂不能创建转写任务。

### 1.2 运行边界

应用面向本机单用户。客户端自动启动随机回环端口的私有服务，通过启动时访问令牌鉴权；8765 仅作为独立后端开发端口。一个服务进程内，同一时刻只允许一个转写任务，模型预加载也与转写任务互斥。

「单任务」限制依赖进程内状态，不是跨进程锁。当前必须以单个 Uvicorn worker 运行，不能通过增加 worker 数量直接扩容。

## 2. 技术选型与总体架构

### 2.1 前端

前端使用 Vue 3、TypeScript、Ant Design Vue 和 Vite。Vue 管理录音状态、历史列表、校对操作及文档预览；Ant Design Vue 提供表单、按钮、弹窗、标签和消息提示；TypeScript 定义请求及响应的数据形状。

当前主要界面集中在 `frontend/src/App.vue`，网络封装、接口类型与 Markdown 预览生成函数位于 `frontend/src/api.ts`，样式位于 `frontend/src/style.css`。

### 2.2 后端

后端使用 Python 和 FastAPI，负责参数校验、任务启动与停止、音频处理、识别调度、历史数据查询、文本修改和导出。

SQLite 保存任务元信息与文字段落，文件系统只保存识别所需的临时音频片段及模型缓存，当前任务不持久保存完整录音。当前没有引入 Redis、独立任务队列、消息代理或数据库服务。

### 2.3 原生采集组件

macOS 系统声音由 Swift 编写的 `ParrotCapture` 采集。组件通过 ScreenCaptureKit 获取音频，向标准输出持续写入 PCM 数据，由 Python 读取。

界面不通过麦克风监听扬声器。客户端宿主启动 Python 服务，由应用包内的原生进程承担系统声音采集。收起工作区不会停止后台任务，退出客户端则停止采集并收尾。

### 2.4 本地识别

默认选择 Whisper large-v3。Apple Silicon 设备在安装 MLX Whisper 的情况下优先选择 MLX；其他情况下自动选择 faster-whisper。当前 faster-whisper 分支明确使用 CPU 与 int8 计算，没有实现 CUDA 配置。

该选型适合当前中英文、本地识别的需求。准确率仍受语音、口音、音乐和专业术语影响，不能把选择大模型等同于无错误识别。

### 2.5 调用关系

客户端 WKWebView 经带访问令牌的本机 HTTP 请求调用 FastAPI。FastAPI 将任务交给 `TranscriptionService`，服务启动原生系统声音采集进程，再由 `Chunker` 产生磁盘片段。单独的识别线程执行模型推理，将结果写入 SQLite。客户端界面轮询服务状态与记录详情，展示增量结果。原生宿主另行轮询服务状态更新悬浮球。

客户端应用包中，FastAPI 为 WKWebView 提供打包后的静态资源。独立界面开发时，Vite 将 `/api` 代理到开发后端；该开发模式不包含原生悬浮球。

## 3. 代码组织与模块职责

- `backend/main.py`：应用入口、HTTP 接口、访问来源限制、静态文件托管和生命周期管理。
- `backend/config.py`：数据路径、模型缓存环境、平台识别、采集程序位置和采样率。
- `backend/schemas.py`：识别配置与文本编辑请求的 Pydantic 模型。
- `backend/service.py`：任务互斥、后台任务、采集进程、生产者与消费者协调、停止及退出。
- `backend/audio.py`：WAV 写入与音频分段。
- `backend/asr.py`：识别引擎选择、模型加载、VAD、推理和结果清理。
- `backend/store.py`：SQLite 建表、事务、查询、段落修改及 Markdown 导出。
- `backend/warmup.py`：命令行模型预加载。
- `frontend/src/App.vue`：工作台页面、轮询、交互和校对流程。
- `frontend/src/api.ts`：前端数据类型、带令牌的 HTTP 封装、时间与 Markdown 格式化。
- `frontend/src/desktop.ts`：原生收起、复制、导出与悬浮球状态桥接。
- `native/ParrotDesktop.swift`：macOS 悬浮球、工作区窗口、菜单与后台服务生命周期。
- `backend/desktop_server.py`：客户端私有服务及父进程存活监控。
- `native/SystemAudioCapture.swift`：macOS 系统声音采集实现。
- `scripts/setup.sh`：安装依赖并构建前端、原生采集和客户端。
- `scripts/start.sh`：打开 `dist/Parrot.app`。
- `scripts/start-backend.sh`：仅供独立界面开发的本地后端入口。
- `scripts/build-client.py`：打包本机 `.app`。
- `scripts/test-client.py`：隔离数据下的原生客户端集成验证。
- `scripts/build-capture.sh`：编译 `native/bin/ParrotCapture`，部署目标为 macOS 13.0。
- `tests/test_pipeline.py`：音频处理、任务停止、存储和接口流程测试。
- `tests/conftest.py`：在导入后端前设置隔离的数据目录，保护实际使用中的数据库。

新功能应优先放在对应职责模块。未来新增音源时应适配为规范化 PCM；新增识别引擎应输出现有段落格式；新的笔记整理能力应在转写结果之上建立单独模块。

## 4. 核心业务流程

### 4.1 系统声音转写

1. 用户选择语言、模型和引擎，点击「开始聆听」。新记录使用默认名称，可通过 Markdown 一级标题改名。
2. 前端提交 `POST /api/sessions`。
3. 后端检查任务互斥、操作系统和采集组件是否存在，创建 `preparing` 状态的记录，立即返回记录详情。
4. 后台任务加载或复用模型。模型准备完成之前不启动声音采集。
5. 后端启动 `ParrotCapture`，并行读取其标准输出和标准错误。
6. 原生进程成功启动采集后，在标准错误输出独立一行 `READY`。Python 收到该标记，将状态改为 `recording`。
7. 后端将声音直接交给分段器，不写入完整 `audio.wav`；临时片段生成后入队，由识别消费者持续处理。
8. 识别后的段落及处理进度写入数据库，前端轮询显示结果。
9. 用户停止后，后端结束采集，处理尾部片段并等待队列处理完成，再将记录设为 `completed`。

使用者应在界面显示「正在聆听」后播放课程，避免在模型加载或权限等待期间错过开头。

### 4.2 校对与导出

用户选择历史记录，通过只读时间标记区分片段，界面不提供播放器或点击回听。修改某个段落时，前端提交对应段落 ID 和新文字。保存操作只更新当前文字并清除该段的待校对标记，识别原文继续保留。

Markdown 预览由前端生成，导出内容由后端生成，客户端通过 NSSavePanel 选择保存位置；复制通过 NSPasteboard 完成。二者都使用同一记录中当前的段落文字。导出包含标题、UTC 创建时间、模型和音频总时长，正文按原有顺序逐行排列，不生成段落时间戳标题，也不插入空白行；清除各行首尾空白和空内容段落，但保留英文单词之间的空格。待校对段落在文字前保留「（待校对）」提示；不自动生成总结或纠错内容。前端预览、复制和后端导出遵循同一格式，转写列表只保留只读时间标记，不具有回听功能。

导出接口未禁止活动任务，因此处理中也能下载已识别内容的快照，但完整笔记应在任务完成后导出。

## 5. 系统声音采集设计

### 5.1 权限与音源

原生进程要求 macOS 13 或更新版本。首次使用通常需要在「隐私与安全性 → 屏幕与系统音频录制」中授权启动后端的终端或应用，授权后可能需要重启该终端或应用。

实现选择首个可用显示器构造 ScreenCaptureKit 过滤器，包含该过滤器范围内的应用音频，不提供单应用选择。受保护媒体可能无法采集，无显示器环境也可能无法启动。

配置启用音频，采样率为 16000Hz、单声道，并设置较小的视频尺寸与较低帧率。当前只注册音频输出，不注册或保存画面输出，也不采集麦克风。

### 5.2 进程通信约定

标准输出只包含裸 PCM16 音频，禁止混入日志、JSON 或提示文字。标准错误传输 `READY` 和错误说明。更改原生日志行为时必须保留这一约定，否则会把文本当作声音识别。

原生组件确认系统返回 Float32、16kHz、单声道数据，限幅后转换为小端 Int16。若格式不符合约定或无法复制采样，组件输出诊断信息并以非零状态退出。

Python 端将任意大小的管道读取结果暂存为字节缓冲区，按每批 3200 字节处理。该大小对应 100ms 音频，可以避免一次读取刚好截断一个采样值，也使静音判断不依赖操作系统管道读包大小。结束时对不足一批的尾部按 16 位采样边界补充处理。

### 5.3 显示电平与采集上限

界面电平来自最新一批声音的 `min(1, RMS * 8)`，只用于显示，不是音质分数，也不会写入数据库。

系统采集达到 8 小时对应的音频采样数时主动停止。该时长依据收到的采样累计，不是独立的墙钟计时器。

## 6. 音频规范化与分段

### 6.1 统一格式

进入分段器和识别链路的声音统一为 16000Hz、单声道、小端有符号 16 位 PCM。识别前将 Int16 转为 float32，并除以 32768，转换到近似 `[-1, 1]`。

每秒音频占 `16000 * 1 * 2 = 32000` 字节，不计 WAV 文件头时每小时约 115.2MB。这个值可用于估算采集数据流和积压临时片段的体积；1.0 不会按整堂课程保存完整录音。

音频格式由原生采集组件确认和转换；1.0 没有文件解码、重采样入口，也不直接依赖 python-multipart。识别引擎自身的传递依赖由相应库管理。

### 6.2 分段策略

`Chunker` 持有当前 PCM 缓冲和累计采样位置。每次 `feed()` 后计算当前批次 RMS：低于 0.006 时累计静音长度，否则清零。

满足下列任一条件时输出片段：

- 当前缓冲已达到约 24 秒。
- 当前缓冲已达到约 8 秒，且连续静音采样累计达到 0.6 秒。

这是按输入帧检查的目标边界，实际片段可能因一次输入帧的长度略超目标。保留的上下文也计入下一片段的缓冲长度，所以 8–24 秒并不等于每次固定新增的音频长度，更不等于端到端延迟承诺。

普通切片保留末尾 1 秒，作为下一片的上下文。停止采集时调用 `finish()`，只输出尚未覆盖的新采样；如果缓冲中仅剩上次已覆盖的上下文，不再重复输出。

### 6.3 片段元数据

每个 `Chunk` 包含四个属性：

- `path`：待识别 WAV 片段路径。
- `offset`：片段开头在累计采集音频时间轴中的秒数，包含重叠上下文。
- `cutoff`：上个片段已经覆盖到的绝对秒数，用于去除重叠结果。
- `end`：本片段结尾在累计采集音频时间轴中的绝对秒数。

例如上一片覆盖到第 24 秒，下一片可能从第 23 秒开始，此时 `offset=23`、`cutoff=24`。识别时仍读入第 23 秒开始的上下文，保存结果时再排除已归属于前一片的词。

### 6.4 时间戳和去重

有词级时间戳时，计算每个词的绝对时间中点：`offset + (word.start + word.end) / 2`。只保留中点不早于 `cutoff` 的词，再将保留下来的词重新组合为段落。

没有词级数据时，用整个识别段落的时间中点进行相同判断。最后将起点限制在 `cutoff` 之后，终点限制在 `end` 之前，丢弃空文字或无有效时长的结果，时间戳保留三位小数。

该方法按时间归属去重，不按文字相等去重，因此不会因为相邻句子的内容相同就直接删除真实复述。词级时间本身有误差，跨边界词仍可能受截断影响，后续准确率测试应包含连续讲话与边界样本。

时间戳以累计采集采样数为基准，不关联播放器原视频的播放进度。课程暂停、跳转、倍速或采集期间的音频间隙，都不能据此直接映射为原视频时间。

## 7. 语音识别设计

### 7.1 引擎与模型

配置支持 `engine=auto`、`mlx`、`faster-whisper`。

自动模式只根据平台和 MLX Whisper 包是否存在进行选择。MLX 加载或推理失败后不会自动转为 faster-whisper；用户需要修改引擎后重试。明确指定 MLX 而设备不是 Apple Silicon 时会报错。

模型支持 `large-v3`、`large-v3-turbo` 和 `small`，默认 `large-v3`。MLX 分支映射到以下模型标识：

- `large-v3`：`mlx-community/whisper-large-v3-mlx`。
- `large-v3-turbo`：`mlx-community/whisper-large-v3-turbo`。
- `small`：`mlx-community/whisper-small-mlx`。

faster-whisper 直接使用对应的模型名，使用 `device="cpu"`、`compute_type="int8"`。切换引擎可能需要分别缓存模型文件，不能假设不同引擎共享同一份模型权重。

### 7.2 加载与复用

模型缓存键为 `(engine, model)`。当前模型已就绪且缓存键相同时直接复用。模型状态独立于记录状态，包含 `idle`、`loading`、`ready` 和 `error`，通过 `/api/status` 返回。

首次模型下载依赖网络。Large v3 的历史实际下载约为 2.9GB，但不能据此估计其他模型、其他引擎或后续版本的精确大小。模型下载和加载过程的详细进度目前由后端终端展示，界面只显示状态与说明。

### 7.3 静音与非语音处理

识别前先排除空数据和绝对峰值小于 0.001 的片段，再调用 faster-whisper 提供的 Silero VAD，参数 `min_silence_duration_ms=500`。VAD 没有检测到语音时，整片跳过识别。

这层 VAD 同时用于两个引擎，因此 MLX 模式仍依赖 faster-whisper 及其 VAD 运行环境。MLX 分支把完整片段送入模型，不在应用层拼接 VAD 找到的语音区间，以保持原时间轴。faster-whisper 推理时还开启其自身的 `vad_filter=True`。

### 7.4 识别参数

通用参数包括：`temperature=0.0`、`condition_on_previous_text=False`、`word_timestamps=True` 和 `no_speech_threshold=0.6`。faster-whisper 额外使用 `beam_size=5`。

关闭跨片段文本条件可降低错误内容持续重复的风险；片段前的 1 秒音频上下文仍会保留。当前参数没有在本项目课程数据集上完成系统调优。

中文和自动语言模式使用固定的简体中文课程提示，英文模式使用固定的英文课程提示。已移除用户配置的专业术语提示；历史记录中的旧术语不再用于识别。自动语言检测不保证每个词都能正确判断语言切换。

### 7.5 待校对标记

结果中的 `avg_logprob < -0.8` 时，将段落 `review` 设为 1；非有限数值按 -2 处理。这个标记是启发式提示，不是经过校准的准确率或错误概率。未被标记的段落也可能出现同音字、术语及断句错误。

词级时间戳仅用于清理当前结果，当前数据库不保存词级信息。后续若需要逐字高亮或词级对齐，需要扩充持久化结构。

## 8. 并发、队列与停止语义

### 8.1 执行单元

HTTP 请求与任务调度运行于 asyncio 事件循环。模型加载和推理统一放进 `ThreadPoolExecutor(max_workers=1)`，避免直接阻塞事件循环，并让 MLX 模型操作保持在同一专用线程。

系统音频使用异步子进程管道读取，产生的磁盘片段由 asyncio 队列交给识别消费者。停止标记使用线程事件，只执行同步置位和读取，避免绑定特定事件循环。

### 8.2 背压与资源

队列保存的是 `Chunk` 路径及元数据，PCM 内容先写到磁盘，不会将整堂课程的待识别音频堆在内存中。单片识别完成或失败后，消费者删除该片段文件。任务结束的清理逻辑还会删除该记录下尚未消费的 `chunk-*.wav`，覆盖正常完成、失败和协程取消；不删除历史完整录音文件。

当前队列没有容量上限，也没有磁盘配额或自动降速机制。推理慢于采集时，会增加待处理片段数量、磁盘使用量和用户等待时间。此处只是控制音频内存占用，并未完全解决背压。

前端用 `max(0, duration - processed)` 展示待处理音频时长。这是剩余音频量，不是预计剩余计算时间；静音片段跳过识别后仍会更新 `processed`。

### 8.3 用户停止

停止接口设置停止事件，将记录状态设为 `stopping`。系统声音采集进程收到终止信号，管道中剩余音频继续收尾处理。

生产者收尾后，剩余有效采样通过 `finish()` 入队；生产者向队列写入结束标记，消费者处理已入队片段后退出。只有等待消费者成功结束，记录才转为 `completed`。

因此「停止」指停止产生新的音频输入，不是立即取消所有已排队推理。推理慢于播放时，点击停止仍可能需要处理较多已排队音频。

在模型加载阶段停止不会立即取消正在执行的模型加载线程；模型准备返回后，任务检查停止事件并结束，不启动采集。

### 8.4 服务退出

FastAPI 退出时取消独立的预加载协程，再调用服务关闭逻辑。关闭逻辑先停止采集，最多等待当前任务 10 秒；超过时限会取消任务协程并将记录标为 `interrupted`。

这与用户点击停止后持续等待队列完成不同。取消协程也不等于立即中断已经执行的线程计算，不能承诺直接退出进程时一定完成所有剩余推理。需要完整保存时，应先在界面停止并等待任务完成，再退出或重启后端。

## 9. 状态机与恢复

### 9.1 记录状态

- `preparing`：记录已建立，模型或采集权限尚在准备。
- `recording`：系统采集组件已返回 `READY`，正在读取声音。
- `pausing`：正在关闭采集进程、排空已采集的管道尾部。
- `paused`：采集进程已退出，累计时长停止增加；已采集片段继续识别。
- `resuming`：正在启动新的采集进程，等待 `READY`。
- `stopping`：停止继续采集，并处理剩余队列。
- `completed`：生产者与识别消费者正常结束。
- `failed`：模型、采集或识别等环节抛出异常。
- `interrupted`：服务退出取消任务，或启动时发现上次遗留的活动状态。

系统任务通常依次经历 `preparing`、`recording`、`stopping`、`completed`。在准备阶段停止时也可能直接完成，且没有音频和文字。

前端将 `preparing`、`recording`、`pausing`、`paused`、`resuming` 和 `stopping` 视为活动状态。`completed` 表示流程正常结束，不意味着一定识别出文字；纯静音或被 VAD 全部排除的音频可以正常完成而没有段落。

### 9.2 重启恢复

初始化 `Store` 时，会将数据库中 `preparing`、`recording`、`pausing`、`paused`、`resuming` 和 `stopping` 的记录统一改为 `interrupted`，写入重启提示。恢复逻辑仍兼容早期版本遗留的 `transcribing` 状态，但 1.0 不会再创建该状态。

已经提交的文字保留，但没有实现任务自动续跑、待处理队列重建或强制终止后残留片段的启动清理。不能将「保留已写数据」理解为崩溃后无损恢复整个任务。

## 10. 数据与文件设计

### 10.1 数据目录

默认数据目录为项目根目录的 `.data/`。典型内容包括：

- `soundscribe.db`：SQLite 数据库，沿用旧名称以兼容历史记录。
- `soundscribe.db-wal` 与 `soundscribe.db-shm`：SQLite WAL 模式运行期间可能存在的伴随文件。
- 1.0 不再创建 `<session_id>/audio.wav`。旧版本已有的完整录音文件保持原样，不通过接口或界面提供访问。
- `<session_id>/chunk-000000.wav` 等：等待识别的临时音频片段；任务退出时清理，进程被强制终止时可能残留。
- `models/`：默认模型缓存目录。

记录 ID 使用 `uuid.uuid4().hex`，是 32 位小写十六进制字符串。临时片段路径由后端生成；1.0 已移除录音访问接口，不接受客户端提供的音频路径。

### 10.2 sessions 表

`sessions` 表保存记录级信息：

- `id TEXT PRIMARY KEY`：记录标识。
- `title TEXT NOT NULL`：笔记标题。
- `source TEXT NOT NULL`：新建记录固定为 `system`。历史记录可以保留早期版本的 `file` 值，1.0 只允许查看、校对和导出这些历史文字记录，不再提供创建入口。
- `created_at TEXT NOT NULL`：UTC ISO 8601 创建时间，界面转换为本地时间展示。
- `status TEXT NOT NULL`：任务状态。
- `language TEXT NOT NULL`：`auto`、`zh` 或 `en`。
- `model TEXT NOT NULL`：请求的模型名。
- `engine TEXT NOT NULL`：初始请求引擎；模型准备完成后写为实际使用的引擎。
- `vocabulary TEXT NOT NULL DEFAULT ''`：历史兼容列，不再写入、通过接口返回或用于识别。
- `duration REAL NOT NULL DEFAULT 0`：根据累计采集采样数计算的秒数，不代表已保存完整录音。
- `processed REAL NOT NULL DEFAULT 0`：消费者已处理覆盖到的绝对秒数。
- `error TEXT`：失败或中断原因。

当前状态、音源和模型取值主要在应用层约束，数据库没有为这些 TEXT 字段建立枚举 CHECK 约束。

### 10.3 segments 表

`segments` 表保存可编辑段落：

- `id INTEGER PRIMARY KEY AUTOINCREMENT`：段落标识。
- `session_id TEXT NOT NULL`：关联 `sessions.id` 的外键。
- `start REAL NOT NULL`、`end REAL NOT NULL`：累计采集音频时间轴内的绝对秒数。
- `text TEXT NOT NULL`：当前显示、预览和导出的文本。
- `original_text TEXT NOT NULL`：首次识别得到的文本。
- `review INTEGER NOT NULL DEFAULT 0`：待校对标记，0 或 1。

索引 `segments_session(session_id, start)` 用于查询记录的段落，详情查询按 `start, id` 排序。当前未实现记录删除接口，也没有外键级联删除和文本编辑版本历史。

### 10.4 事务与一致性

存储层使用参数化 SQL；动态更新字段名限制在显式白名单内。SQLite 启用 WAL，连接设置 15 秒锁等待超时，并在每次操作后提交或回滚、关闭连接。

一个片段的段落批量插入与记录的 `processed` 更新属于两次独立操作；文件写入与数据库写入也不在同一个事务中。异常退出时，进度、段落与待识别片段可能存在短暂不一致，这是当前恢复设计的限制。

备份应优先停止应用后复制整个数据目录。运行期间只复制 `.db` 文件可能遗漏 WAL 中尚未合并的数据；如果后续要实现在线备份，应使用 SQLite 备份机制并明确是否需要包含模型缓存及旧版本遗留文件。

## 11. HTTP 接口设计

所有应用接口以 `/api` 开头。客户端使用本次启动分配的随机回环端口，并为请求附加 `X-Parrot-Token`；独立开发时基础地址为 `http://127.0.0.1:8765`。标准请求体为 JSON；Markdown 导出返回文件内容。录音接口已移除；即使旧文件仍存在，原 `/api/sessions/{sid}/audio` 地址也返回 404，不暴露历史音频。1.0 不注册上传接口，也不接受 multipart 作为创建任务的请求格式。对原 `/api/sessions/upload` 地址的 POST 请求返回 404 或 405（取决于静态文件挂载），不会创建记录或保存上传文件。FastAPI 交互文档位于 `/docs`，结构定义位于 `/openapi.json`。

### 11.1 通用识别配置

创建任务和预加载模型使用 `Settings`：

```json
{
  "title": "神经网络第一课",
  "language": "zh",
  "model": "large-v3",
  "engine": "auto"
}
```

`title` 长度为 1–120 字符，默认「未命名学习记录」。语言、模型与引擎限定为前述枚举，默认值分别为 `zh`、`large-v3`、`auto`。

前端还会对空白标题补默认学习记录名称；后端字段校验并不等同于前端的空白裁剪。

### 11.2 GET /api/status

返回模型状态对象 `model`、活动记录 ID `active_id`、显示电平 `level`、操作系统 `platform`、Apple 芯片标识 `apple_silicon` 与采集组件可用标识 `capture_available`。

没有转写任务时 `active_id` 为 null；独立预加载期间也可以为 null，因此界面还必须检查 `model.status`。`capture_available` 仅确认平台和二进制文件存在，不代表已经获得系统权限或已经成功录音。

### 11.3 POST /api/model/prepare

接收 `Settings`，空闲时创建后台加载任务，返回 202 及说明文字。客户端应继续查询 `/api/status` 判断 `ready` 或 `error`。返回 202 不代表模型下载或加载已完成。

### 11.4 GET /api/sessions

返回按创建时间倒序排列的记录数组。每项包含记录字段和 `segment_count`，不附带全部段落。当前没有分页或搜索参数。

### 11.5 POST /api/sessions

创建系统声音任务，接收 `Settings`，成功返回 201 和刚创建的记录详情。模型加载与采集在响应后异步进行，后续失败通过记录 `status` 和 `error` 展示。

### 11.6 GET /api/sessions/{sid}

返回记录字段及 `segments` 数组。段落具有 ID、所属记录 ID、时间戳、当前文字、识别原文和待校对标记。记录不存在时返回 404。

### 11.7 POST /api/sessions/{sid}/stop

返回 202 及当前记录快照。只有该 ID 正好是当前活动记录时才执行停止。对已结束的现有记录重复调用不会再创建任务，仍返回记录快照。客户端需要轮询直到终态，不能把 202 当成完成信号。

### 11.8 PATCH /api/sessions/{sid}/segments/{segment_id}

接收 `{"text": "校对后的内容"}`，最长 10000 字符，允许空字符串。成功返回 `{"ok": true}`，更新 `text` 并将 `review` 设为 0，保留 `original_text`。记录或对应段落不存在时返回 404。

### 11.9 GET /api/sessions/{sid}/markdown

返回 UTF-8 Markdown 和附件下载响应头。文件名来自记录标题，路径分隔符替换为下划线，经过 URL 编码后使用 `filename*` 传输，支持中文文件名。

### 11.10 错误语义

- 400：系统采集平台或组件条件不满足。
- 403：Host 或 Origin 不符合本地访问约束。
- 404：记录、段落不存在，或请求了已移除的录音接口。
- 409：已有互斥任务。
- 422：JSON 或字段约束校验失败。

后台异常通常不会改变已经返回的创建请求响应，而是将记录设为 `failed` 并保存错误；预加载失败写入模型状态。HTTP 层其他未处理异常仍可能返回 500。前端优先展示字符串形式的 `detail`，无法直接展示结构化校验详情时使用通用状态码提示。

## 12. 前端交互与状态同步

客户端工作区包括顶部操作栏、紧凑声音采集区、转写与 Markdown 标签页；历史与设置通过弹窗打开。1.0 不显示原始录音播放器。历史记录、处理时长、段落数量等来自实际接口，没有演示数据填充。

`refresh()` 并行读取服务状态和历史列表，再读取当前选中记录的详情。在本次请求链结束后，使用 `setTimeout(..., 1000)` 安排下一次刷新，因此实际刷新间隔是请求耗时加约 1 秒，不是严格每秒，也不是 WebSocket、SSE 或后台主动推送。

页面通过 `selectionRevision` 和记录 ID 判断异步详情是否仍对应当前选择，避免快速切换记录后被旧响应覆盖。编辑中的输入单独保存在 `editText`，轮询不直接覆盖编辑输入。

片段时间标记仅用于阅读定位，不是可点击的回听按钮。启用「跟随最新内容」且未编辑段落时，收到新增段落后自动滚动。收起或关闭工作区窗口会保留 WebView 和后台任务；重新展开时继续使用当前状态。整个客户端退出则由原生宿主停止服务。

预览以文本形式展示 Markdown 源码，不将转写内容直接渲染为 HTML。客户端复制与保存由原生桥接执行，保存内容通过带令牌的真实后端接口获取；仅独立开发预览保留浏览器能力回退。

当前每次读取详情都会取回全部段落，列表也没有分页。长课程、大量历史记录和重复运行的调试界面会增加重复传输与查询负担，这是后续分页、增量同步或推送方案的切入点。

## 13. 配置、安装与部署

### 13.1 环境变量

- `PARROT_DATA`：数据根目录，默认项目根目录 `.data/`；兼容旧变量 `SOUNDSCRIBE_DATA`，新变量优先。
- `PARROT_PORT`：仅独立后端开发入口使用的端口，默认 8765。原生客户端自动分配随机端口。
- `PARROT_PYTHON`：可覆盖本机构建/测试使用的 Python 解释器路径。
- `PARROT_DESKTOP_TOKEN`：客户端生成并传给私有服务的启动令牌，不应由用户固定保存。
- `PARROT_CAPTURE_BINARY`：客户端指定的应用包内采集程序位置。
- `HF_HOME`：未由外部设置时，应用默认设为数据目录下的 `models/`。外部自定义 HF_HOME 时，MLX/Hugging Face 缓存可能位于其他位置；faster-whisper 仍显式使用数据目录内的模型子目录。

当前没有 `.env` 文件自动加载逻辑。环境变量需要通过终端或启动环境传入。`PARROT_PORT` 是独立开发后端的启动配置，直接运行 Uvicorn 时应使用其 `--port` 参数；修改后端开发端口时也要同步调整 Vite 代理目标。

### 13.2 首次安装与日常运行

Python 要求 3.9 或以上，建议 3.11/3.12；Node.js 需满足现有 Vite 的引擎要求，项目说明使用 20.19 系列或 22.12 及以上版本。Mac 原生编译需要 Xcode Command Line Tools。

在项目根目录运行：

```bash
bash scripts/setup.sh
bash scripts/start.sh
```

安装脚本创建 `.venv`、安装 Python 依赖、编译原生组件，并使用存在的前端 lockfile 执行 `npm ci` 后构建。客户端安装脚本当前仅支持 macOS。

安装完成后双击 `dist/Parrot.app`，或用 `start.command` / `scripts/start.sh` 打开客户端。后端由客户端自动启动和管理，不再以浏览器作为日常入口。当前应用包引用本机 Python 环境和共享数据，尚非可跨机器直接安装的发行包。

### 13.3 开发运行

仅调试独立 Vue 界面时使用以下方式；不要与使用同一数据目录的客户端同时运行。后端终端：

```bash
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8765 --reload
```

前端终端：

```bash
cd frontend
npm run dev
```

浏览器访问 `http://127.0.0.1:5173`。开发重载会重建进程，因此不应在需要完整保留的活动录音期间修改后端代码。

### 13.4 更新与发布

更新前先从菜单栏退出客户端并备份数据。安装依赖、重建前端后，运行 `.venv/bin/python scripts/build-client.py` 重新生成应用，再启动客户端。数据库当前只有建表逻辑，没有正式的版本迁移框架，后续改变表结构时必须另行设计迁移和回退。

FastAPI 只会在 Python 导入应用模块时发现 `frontend/dist` 存在的情况下挂载前端。新安装环境应先构建再启动。编译出的原生组件、模型、缓存、虚拟环境、环境配置及 `.data/` 不提交到 Git。

## 14. 故障处理、可观测性与安全边界

### 14.1 故障处理

模型加载失败后保留模型错误状态；创建过的任务还会设为 `failed`。当前不会自动更换模型或自动重试下载。

采集权限、显示器或格式不满足时，由原生组件输出错误，后端记录失败原因。识别消费者异常时会请求停止采集，避免声音无限继续进入未被处理的队列。

成功、失败或正常停止后，只持久保留已写入数据库的文字与元信息，并清理识别用临时片段。1.0 不保存完整录音，因此不能事后通过录音重试识别；未识别内容需要重新播放并创建任务。硬退出仍可能遗留临时片段，当前没有启动时全量清理机制。

### 14.2 日志与指标

目前主要依赖 Uvicorn 访问日志、Python 异常日志、模型下载终端输出和原生标准错误。错误日志通过 session ID 关联任务，界面还可观察记录状态、`duration`、`processed`、段落数量和待处理音频时长。

尚未实现结构化日志、持久化任务事件、片段级耗时统计和崩溃报告。后续可增加推理实时率 `推理耗时 / 音频时长`、队列长度、模型加载耗时和磁盘用量，用来区分采集、推理或存储瓶颈。

### 14.3 本地访问约束

客户端私有服务只监听回环地址，通过每次启动生成的桌面访问令牌保护 API 和接口文档。独立开发模式没有账户体系，默认不设置桌面令牌。应用检查本机 Host 和允许的 Origin，开发模式允许本地 5173 来源；`testserver` 是测试保留 Host。该机制用于减少跨站调用和错误暴露，不是公网部署所需的认证授权方案。

系统声音处理、模型加载和文件写入都在本机发生，模型下载需要访问外部模型源。当前不会主动把录音或文本提交给云端识别或总结服务。若以后加入云端 AI，应将上传内容、用户授权及数据保留规则作为独立设计事项。

历史依赖检查在 README 和验证记录中保留了开发依赖公告。发布时应基于当时的依赖版本重新执行审查，不应把历史审查结果视为持续有效的结论。

## 15. 测试与验收设计

### 15.1 当前自动测试

当前 `tests/test_pipeline.py` 包含 17 个测试用例（含参数化平台用例），覆盖：

- 分段尾部完整保留、上下文重叠与纯上下文尾部不重复输出。
- 基于词级时间戳的重叠清理与待校对标记。
- 启动时将遗留活动记录标为中断。
- 系统采集任务、文字持久化、校对与导出链路；真实管道读取路径不保存完整录音。
- 无效设置、未知记录、未知段落、不支持的平台，以及上传和录音接口已移除。
- 历史录音文件保留但不可通过接口访问，识别失败后所有排队片段被清理。
- 非允许 Origin 与 Host 的拒绝，以及客户端令牌缺失或错误时的拒绝。
- 停止采集后处理最后的短片段，以及准备阶段停止后不启动采集。

接口和任务流程测试使用采集与识别替身，分段、WAV 写入和数据库操作使用真实实现。这些测试可以验证控制流程，不代表真实模型字错率或系统录音权限已通过验证。

在项目根目录运行：

```bash
.venv/bin/python -m pip install -r backend/requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/ruff check backend tests
```

前端运行 `npm run build` 验证 Vue/TypeScript 与构建。在 macOS 图形会话中执行 `.venv/bin/python scripts/test-client.py`，以独立临时数据库验证真实 AppKit 窗口、WebKit、桥接及私有后端；测试不自动采集声音或修改实际历史记录。

### 15.2 实际模型与平台验收

模型预加载可以单独运行：

```bash
.venv/bin/python -m backend.warmup --model large-v3
```

系统采集需要在具有实际系统权限的 Mac 上验证。至少检查佩戴耳机的课程音频、首次权限拒绝后恢复、静音开始与结束、连续讲话跨片段、停止尾部、悬浮球展开收起、面板关闭后持续转写、播放暂停与客户端退出。

准确率评估应准备有人工参考文本的中文、英文及中英混合课程，另包含专业术语、音乐和不同口音。中文可统计字错率，英文可统计词错率，同时记录边界重复、漏字和静音幻觉。当前没有正式课程标注集，也没有承诺或验证统一准确率指标。

### 15.3 当前版本验收原则

完成一段课程后，应能重新打开历史记录，校对文字并导出一致的 Markdown，同时确认没有原始录音播放器或录音接口，新任务不留下完整录音文件。停止后不遗漏尚未形成完整分段的有效尾部。无语音的任务允许产生零段文字；任何失败必须可从任务或模型状态中区分，不能仅依据创建接口成功判断转写成功。

## 16. 后续演进建议

以下内容是规划，不属于当前已实现能力。

### 16.1 优先完善转写基础

先建立课程样本与准确率基线，再评估模型、提示词及分段参数。补充结构化日志、推理实时率、磁盘配额、队列背压、失败片段重试、任务恢复及临时文件清理。界面可明确区分停止采集与取消剩余识别。

对于跨平台系统采集，应为 Windows 和 Linux 分别实现适配器，并继续输出统一 PCM。macOS 可增加单应用音源选择。上述改动不应耦合进识别器本身。

### 16.2 丰富学习笔记

在稳定转写后增加课程来源实体，明确原视频时间与采集音频时间的映射，再引入手动或自动截图。截图应记录对应来源、采集时间、标题、说明和本地资源路径。

知识整理应将原始转写与派生笔记分开保存。章节、摘要、术语解释、知识点和复习问题应保留生成版本、来源段落和用户修改，避免重新生成时覆盖人工校对内容。引入云端模型时还应提供清晰的数据发送边界。

### 16.3 面向长期维护的模块拆分

前端可以按历史列表、采集控制、识别设置、转写编辑器和 Markdown 区域拆成组件，并将轮询与选中状态提取为组合式函数。后端可增加明确的音源和识别器接口，逐步引入配置对象、数据库迁移和可持久化任务事件。

当全量轮询成为瓶颈时，再实现记录分页、段落增量查询或 SSE/WebSocket。若要支持多个用户或多个 worker，应先把全局任务与模型状态外置，并设计录音权限、用户数据和设备资源的隔离，不能直接将当前进程内单例部署为共享服务。

## 17. 文档维护约定

接口变更应同步更新请求类型、Pydantic 模型、本文章节和对应测试；数据库变更还应补充迁移说明。调整音频格式、分段边界、去重或停止行为时，需要重新验证尾部、时间戳和导出一致性。

新增能力只有在代码、可运行验证及已知边界明确后，才从「后续演进」移入「当前实现」。运行记录继续维护在 `docs/VALIDATION.md`，本目录用于保存开发设计资料。

## 18. 暂停与继续补充

新增 `POST /api/sessions/{sid}/pause` 和 `POST /api/sessions/{sid}/resume`，无请求体，成功返回 202 和最新记录详情。记录不存在返回 404；非当前活动记录、状态不支持当前操作返回 409。暂停仅接受 `recording`，继续仅接受 `paused`。

暂停结束当前采集进程而非挂起进程，尾部正常提交识别后进入 `paused`。期间不启动采集进程、音量归零、累计时长保持不变，仍允许处理已有识别队列。继续复用同一会话、同一个识别器和累计采样位置，重新启动采集进程，收到 `READY` 后恢复聆听。片段序号持续递增，暂停边界不保留旧上下文。

暂停等待由事件驱动，停止和退出都会唤醒，不会因等待继续而无法关闭。重启恢复覆盖新增中间状态。对应验证包含尾部保留、恢复后片段偏移、暂停时长不增加、暂停后停止/退出、恢复失败、非法状态和其他记录隔离，以及恰好落在分段边界时的上下文清理。
